# HDR-SC: Hierarchical Dual-Risk Support Construction

HDR-SC constructs a fixed normal support set before deployment. It first
screens candidates by detector-native image risk, then minimizes spatial
dispersion within the adaptive near-optimal set. The detector is unchanged.

This is the method core, not the complete paper-reproduction pipeline.
It includes the selection algorithm, adapter interface, synthetic example,
environment references and tests. It does not include datasets, detector
source code, weights, experimental caches or paper results.

## Algorithm

Given a fixed verified-normal pool P_B and support size K < B:

1. Generate up to M unique candidate supports. Enumerate all combinations when
   they fit within M; otherwise sample unique combinations deterministically.
2. For every support S, fit the target detector and score only V(S) = P_B minus S:

   `Q_img(S) = Mean_x a_S(x) + beta * MeanTop10%_x a_S(x)`

3. Compute the adaptive image-risk gate over all candidates:

   `MAD_Q = median(abs(Q_img - median(Q_img)))`

   `epsilon = 0.5 * MAD_Q`

   `Omega = {S: Q_img(S) <= min(Q_img) + epsilon}`

4. Only for retained candidates, reduce each native normal-image anomaly map:

   `r_spatial(S,x) = Mean(A_S(x)) / max(MeanTop1%(A_S(x)), 1e-12)`

   `R_spatial(S) = Mean_x r_spatial(S,x) + MeanTop10%_x r_spatial(S,x)`

5. Select `argmin_{S in Omega} R_spatial(S)` and refit that support for deployment.

The gate uses an absolute 1e-12 roundoff slack, matching the current experiment
runner. A singleton gate skips spatial inference and selects its only member;
its R_spatial is reported as null, not zero. All top-fraction counts use ceil
with a minimum of one. An all-zero map has dispersion zero. Maps must be finite,
nonnegative native H x W responses; no per-map rescaling is introduced.
Spatial aggregation uses fixed equal weights, independent of beta.

This is not a weighted image/spatial sum or a fixed top-10% candidate shortlist.
Only verified normal pool images are used; no test image, mask, metric or query
feedback enters selection. Pool identity and ordering must remain fixed for
paired comparisons. Matching a seed alone does not reproduce candidate lists
generated by another implementation; compare the exported indices explicitly.

## Installation

```bash
conda env create -f environment.yml
conda activate hdr-sc-core
python -m pip install -e .
```

Alternatively install with `python -m pip install -e .` in an existing Python
3.10+ environment. The core requires only NumPy. Install downstream detectors
in their supported environments; see `environments/` and `docs/ADAPTERS.md`.

## Python API

```python
from hdr_sc import HDRSCConfig, HDRSCSelector
from hdr_sc.io import save_selection

config = HDRSCConfig(support_size=4, max_candidates=500, beta=1.0,
                     tail_fraction=0.10, epsilon_weight=0.5, seed=0)
result = HDRSCSelector(config).select(pool_paths, detector_adapter)
print(result.selected.support_indices)
save_selection(result, "output/selection")
```

The adapter exposes prepare, fit, native image score, and one-image anomaly-map
inference. HDR-SC releases each map immediately after reducing it to one scalar.
Only the gate's candidates request maps. See `docs/ADAPTERS.md` for GPU handling.

## Synthetic Example and CLI

Run these commands from the repository root after installation:

```bash
python -m examples.minimal_selection
hdr-sc-select --pool-manifest examples/pool.txt --adapter examples.plugin_adapter:build_adapter --support-size 2 --max-candidates 500 --output output/cli-example
```

`python -m hdr_sc.cli` is equivalent to `hdr-sc-select`. The example uses
synthetic features, not a real anomaly detector or paper measurements.
The YAML under `configs/` documents defaults; the CLI takes explicit options
and does not automatically load YAML. `--adapter-config` accepts detector JSON.

## Output and Reproducibility

- `candidate_ranking.csv`: all supports/complements, image risks, Q_img rank,
  gate membership, R_spatial, spatial rank and selected flag. Rows stay ordered
  by image risk; the winner need not be the first row. Rejected candidates have
  blank spatial scores because their maps were not computed.
- `selected_support.json`: selected paths/indices, configuration, pool ordering,
  gate statistics, selected image rank and spatial score/status.

Default M is 500, beta is 1.0 and lambda (`epsilon_weight`) is 0.5. Image ties
use candidate ID; spatial ties also use candidate ID. Neither detector-native
image scores nor candidate ordering should be imported from a different
detector, category or pool. The core does not silently load research caches.
